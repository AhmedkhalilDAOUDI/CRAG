Keywords used in the CRAG workflow

Every term that appears in the workflow diagram, in plain words.

AI and modelsData and knowledgeSoftware and infrastructureEvaluation
LLMLarge Language Model: a neural network trained on huge text corpora to predict the next token; here it extracts, classifies, grades and writes.
RAGRetrieval-Augmented Generation: fetch relevant text first, then let the LLM answer using only that text.
GraphRAGRAG that also retrieves from a knowledge graph, so answers can follow relations between facts.
Corrective loopThe model grades its evidence and, if weak, rewrites the query and retrieves again (after Yan et al., 2024).
EmbeddingA list of numbers (here 2,048) representing meaning; similar texts get nearby vectors.
PromptThe instructions and context sent to the LLM for one call.
Structured extractionPrompting the LLM to return entities and relations as strict JSON that code can parse.
Intent classificationDeciding what kind of question it is: lookup, expert search or recommendation.
HallucinationA fluent but unsupported claim; citations and grounding prompts reduce it.
NVIDIA NIMNVIDIA's hosted inference API (OpenAI-compatible) that serves the Nemotron chat and embedding models.
Knowledge graphData stored as nodes (things) connected by typed edges (relations).
EntityA node: a person, skill, technology, organisation, project, role, concept, location...
Relation / tripleA typed edge, written (subject, PREDICATE, object), e.g. (Employee 12, HAS_SKILL, SQL).
ChunkA ~1,200-character piece of a document; the unit that is embedded and retrieved.
OverlapThe 200 characters repeated between consecutive chunks so no sentence loses its context.
OCROptical Character Recognition: turns pixels of a scanned page into text (Tesseract).
Entity resolutionMerging different spellings of the same thing into one node.
Entity linkingMapping words in a question to existing graph nodes.
Multi-hopFollowing several edges in a row (A→B→C) to reach facts not stated together.
Cosine similarityAngle-based closeness of two vectors, from -1 to 1; used to rank passages.
Neo4jA graph database; stores nodes, relations and vector indexes.
CypherNeo4j's query language, e.g. MATCH (p)-[:HAS_SKILL]->(s) RETURN p.
Vector index (HNSW)A layered proximity graph that finds nearest vectors without scanning them all.
LangGraphA library that runs an LLM workflow as a graph of steps sharing one state, with conditional edges.
State machineA fixed set of steps and transition rules; here analyze → retrieve → grade → ... → explain.
RRFReciprocal Rank Fusion: merges ranked lists by summing 1/(60 + rank) for each item.
FastAPIThe Python web framework that exposes /api/ask, /api/experts, /api/graph...
Docker / ComposePackages the app and Neo4j into containers that run the same everywhere.
Serverless (Vercel)Hosting where code runs per request; CRAG serves a read-only snapshot there.
Cytoscape.jsThe JavaScript library that draws the graph in the browser.
Precision@5Of the top 5 experts returned, the fraction that are truly from the queried domain.
Hit rateHow often the gold document appears among the retrieved passages.
Exact matchWhether the answer names the correct employee identifier.
LLM-as-a-judgeA model scores correctness and faithfulness from 1 to 5 against a reference.
FaithfulnessWhether every claim in the answer is supported by the retrieved context.
